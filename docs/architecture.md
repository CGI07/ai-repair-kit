# Architecture

- `__main__.py` configures Qt and opens `gui/window.py`. The window owns navigation and themes. `gui/codex_workflow.py` connects diagnosis, preview, approval, and rollback to the existing views. It runs scans on a worker thread.
- `i18n.py` installs Qt catalogs. `preferences.py` handles the application's own settings. The selected Codex folder and diagnostics report are session-only.
- `tools/codex.py` discovers local CLI candidates and data locations without executing Codex. `tools/codex_diagnostics.py` returns bounded findings as codes and counts. It processes only the user config, the optional name index, and selected SQLite metadata columns. It checks file existence without opening rollout files.
- `local_files.py` validates local paths, rejects links and special files, and uses Windows file sharing to guard file access. SQLite normally opens read-only and immutable with a guarded database and no sidecars. For the state and separate Goal stores, the Windows scan can also hold the database, WAL and SHM with read sharing only. It uses SQLite's in-memory WAL index and reads the committed view without using the on-disk SHM index. All aggregate thread, project and rollout checks share the same guarded state connection. The `26.1029.7803.0` historical cache rule may hold a guarded WAL snapshot through the JSON replacement. The other rules require a journal-free state snapshot.
- `tools/codex_repair.py` owns the all-NUL configuration write rule. A preview captures the selected file identity and size. Approval reopens the same file with an exclusive Windows handle, rechecks the exact all-NUL or empty state, and verifies the outcome before closing the handle.
- A recovery backup contains the original all-NUL bytes and a small record with a path-and-file identity digest, byte count and SHA-256. The file is flushed, published without overwrite, and reread before the first target write. A failed write or verification attempts to restore and verify the prior bytes under the same handle. A manual rollback checks that the selected backup still matches the original file identity and that the current content is exactly the repaired empty file.

- `desktop_catalog.py` inspects project schema, Goal IDs and session filenames with bounded read-only access. `desktop_thread.py` checks one thread against guarded stores. The paginated history database and rollout files are checked through file metadata. `desktop_history.py` corroborates the four Desktop cache fields against current metadata.
- `desktop_repair.py` gates writes on the reported build, verified profile metadata, explicit approval and a Windows process check. It serializes replacements with a named mutex, holds the state database read-only during commit, verifies a full cache backup and checks the bytes displaced by `ReplaceFileW`. The verified post-repair hash gates rollback.

Add a new check as a small function returning a finding code and bounded count. Give new repair rules their own narrow eligibility, preview, verification, and failure tests. Keep SQLite migrations, arbitrary TOML rewrites, and session reconstruction separate until their formats and failure modes can be reproduced safely. Keep future AI tool-specific behavior in `tools/` and share only code whose behavior is common.
