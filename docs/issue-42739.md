## Which reports describe the same failure?

The original report concerns Windows 11 and MSIX `26.901.4073.0`. All folders, 14 projects and 54 assigned threads survived while Desktop had an empty local registry and incomplete assignment migration. The app rewrote the cache after startup. Its background processes remained active after the visible window closed. These observations identify a registry mismatch with durable records still present.

Grouping by reporter and explicit follow-up yields **55 distinguishable incident reports** including the body. This is a count of public report groups. It cannot establish the number of independent installations. Comment 1 is a bot duplicate pointer, 50 describes a community tool without a separately documented installation, and 80 adds no case to 42. Comment 81 confirms the symptom and asks for confidence in the repository's security, but provides no version or evidence for classifying a separate recovery case. Reports 56, 65 and 73 are one installation across two recoveries. Reports 70 and 74 describe the same incident.

The common groups describe projects surviving in the state database, App Server, or a historical registry while the current Desktop catalog omits them. Additional conditions include damaged or overwritten cache generations, stale references, duplicate or missing roots, configuration corruption, and a separate account scope. Timing after an update, outage or account switch does not establish causation. Comment 8 attributes malformed timestamps to a custom migration. Comment 10 verified a different active `CODEX_HOME`. Comment 52 concerns a cloud ChatGPT project visible in Classic.

## What the storage layers establish

- The [upstream project migration](https://github.com/openai/codex/blob/rust-v0.158.0/codex-rs/state/migrations/0049_projects.sql) creates projects, ordered roots, original idempotency keys and a nullable `threads.project_id` foreign key. A NULL row can be intentional or reflect a missing link. The [thread source migration](https://github.com/openai/codex/blob/rust-v0.158.0/codex-rs/state/migrations/0030_threads_thread_source.sql) records classification separately. These files establish the core schema. The renderer JSON is version-specific.
- App Server projects and thread metadata can remain available while the sidebar is empty. Comments 6, 7, 26 and 33 report canonical assignments persisting or returning without the Desktop catalog following. This narrows those reports to Desktop registration, projection or rendering in addition to any lost link. It does not identify a single faulty function. [App Server protocol](https://learn.chatgpt.com/docs/app-server)
- The original legacy ID and host map connect the registry to durable project UUIDs. The [signed package inspection](desktop-recovery.md#evidence) confirms the migration keys for `26.1029.7803.0`. Comment 34 reports assignment objects on `26.924.2738.0`. Profile-qualified and account-scoped state require separate evidence. Migration flags describe state. Comment 7 establishes stale references and a failed Desktop result. It does not establish an all-or-nothing migration.

In the inspected Store-signed `26.1029.7803.0` package, the main-process initializer asks App Server for projects, fills an in-memory map of server projects, and separately iterates the existing Desktop registry. Loading ordinary server projects does not, in that path, re-create missing local registry entries. The assignment stage requires a local registry entry to resolve an active destination and reads non-archived threads in pages. It can skip a stale destination. A rejected request can stop the pass before the checkpoint is updated, after other requests have already run. This explains why an available backend, empty registry and incomplete checkpoint can coexist. It does not identify what originally erased the registry or prove the behavior on earlier packages. The migration key combines the host ID and App Server Codex home. AI Repair Kit recognizes matching profile-qualified keys for diagnosis and refuses to choose between conflicting literal and profile-qualified records. The write rules keep their own scope gates.
- The experimental App Server link update lacks a precondition for the previous assignment, as recorded in the [isolated App Server lab](desktop-vm-verification.md). Public reports also show that changing SQLite assignments alone can leave Desktop broken. The product writes verified cache candidates only.
